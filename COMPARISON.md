# How toolrx compares

This is a comparison of scope, not a benchmark. It does not run another
product, and it does not claim a score against one. It states what this
repository measures, how it measures it, and where the deterministic path is
plainly weaker than a general LLM harness.

`toolrx/evaluation_harness.js`. `--check` fails when a measured number or a
quoted block drifts. No model is called and no network request is made; the
harness's fake fetch only reads local files.

## How to reproduce

```sh
python3 toolrx/evaluation.py --write
python3 toolrx/evaluation.py --check
node toolrx/evaluation_harness.js toolrx/web toolrx/web/commands.json toolrx/micro_model.json
```

Every measured program runs twice and the two serialized results are compared
byte for byte. A mismatch fails the report instead of being averaged away. The
harness also counts fetches made after module initialization and refuses a
report when that number is not zero.

## What this does not measure

It does not measure prose quality, world knowledge, image or audio ability,
latency against a hosted model, or whether an unseen sentence will route well.
It measures this repository's own deterministic behaviour. The numbers are
internal to this project; they are not comparable across products.

## Where toolrx is weaker

1. **Conversational breadth.** toolrx follows a fixed route table and checked-in
   phrasing patterns. It can answer a short follow-up, revise the last action,
   and confirm a staged build, but it cannot hold an open-ended conversation,
   ask clarifying questions over many turns, or recover an unseen paraphrase by
   reasoning about it. An unknown sentence falls to the hashed router or refuses
   by name.

2. **General terminal work.** Only allow-listed tools run. There is no arbitrary
   shell, package installation, compiler invocation, port scan, or long-running
   process supervision. The optional Python server adds machine and socket tools,
   but it is still an allow-list, not a terminal.

3. **Generation quality.** Builds come from templates and seeded procedural
   content. The output is coherent, editable, and reproducible, but it is not
   model-quality prose, art, or novel code. A general model will write a better
   paragraph or a more surprising game on the first try.

4. **No learning.** The deterministic path does not improve from usage. There is
   no fine-tuning, embedding index, retrieval, or feedback loop. Adding a
   phrasing or a tool means editing a table, adding evidence, and rebuilding;
   the running app never learns a new route on its own.

5. **Single-user and local.** There are no accounts, sync, collaboration,
   permissions, or cross-device audit trail. Browser storage is the source of
   truth, and two people on two machines do not share a project unless they
   export and import a bundle.

6. **Not a benchmark.** The report counts this repository's own fixtures,
   determinism runs, and one demo build. It is evidence of internal consistency,
   not a held-out evaluation, a human preference study, or a comparison against
   another harness.

If a task needs open-ended language, general system administration, or
model-quality generation, use a general LLM harness. toolrx is for the tasks
that should be boring, inspectable, and repeatable offline.
